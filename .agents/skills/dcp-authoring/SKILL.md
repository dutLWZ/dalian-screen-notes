# DCP 制作与字幕版本管理

## 1. Skill 目标

使用 DCP-o-matic 将视频、音频和字幕制作成影院可播放的 DCP。

主要处理：

- 原始素材检查。
- 字幕封装。
- OV 制作。
- VF 制作。
- 字幕格式选择。
- 字幕位置调整。
- DCP 生成。
- DCP 播放验证。

## 2. 首先区分字幕类型

字幕格式是决定制作复杂度的重要因素。

### 2.1 文本型字幕

常见格式：

- SRT
- ASS / SSA
- 其他 DCP-o-matic 支持的文本字幕格式

特点：

- 字幕内容是文本。
- 可以通过字体渲染生成字幕画面。
- 通常更容易调整字体、字号、位置、行距。
- 可以根据需要修改文本内容。
- 不需要对每条字幕图像进行解析。

一般来说，文本型字幕的处理流程更简单。

但仍然需要检查：

- 编码是否正确。
- 中文字体是否存在。
- 换行是否正确。
- 时间轴是否正确。
- 字体大小和位置是否合理。
- 字体样式是否符合预期。

不要认为只要是 SRT 就一定能直接导入。需要确认 DCP-o-matic 当前版本支持的格式和导入方式。

### 2.2 图像型字幕

常见格式：

- PGS / SUP
- 其他图像字幕格式

特点：

- 字幕不是普通文本，而是图像。
- 每个字幕事件可能包含不同的图像内容。
- 需要读取图像、时间戳和显示信息。
- 字幕位置和缩放可能受原始字幕图像尺寸影响。

PGS 的处理通常比 SRT 更复杂。

本次案例使用的就是 SUP / PGS 字幕。

特别需要检查：

1. 是否成功封装进 MKV。
2. DCP-o-matic 是否识别 PGS 轨道。
3. Timed text 是否启用。
4. Stream 是否选择正确。
5. 字幕是否正确显示。
6. 字幕 Position 是否合理。

### 2.3 字幕格式选择原则

如果能够选择字幕来源：

- 优先考虑时间轴准确、内容完整的文本型字幕。
- 如果必须保留原始图像字幕效果，使用 PGS 等图像型字幕。
- 不要为了追求操作简单而牺牲字幕质量。

如果影片已经有 SUP，但同时也能获得对应的 SRT，可以先比较两者的：

- 时间轴。
- 文本准确性。
- 换行。
- 位置。
- 样式。

再决定使用哪一种。

## 3. OV 制作

OV 是基础版本。

一般包含：

- Picture。
- Sound。

制作步骤：

1. 新建 DCP-o-matic 工程。
2. 导入原始 MKV。
3. 检查视频和音频。
4. 设置画幅、分辨率、帧率。
5. 设置音频语言。
6. 根据影片实际内容设置必要的标记。
7. 生成 DCP。
8. 保留完整 OV 文件夹。

不要在 OV 中添加本次准备通过 VF 添加的字幕。

## 4. VF 制作

VF 是基于 OV 的版本文件。

基本流程：

1. 新建工程。
2. 导入 OV DCP。
3. 导入字幕素材。
4. 设置 Version File。
5. 配置 Refer to。
6. 配置字幕轨道。
7. 调整字幕位置。
8. 生成 VF。

### Refer to

如果 OV 已经包含画面和声音：

| 资源 | 设置 |
|---|---|
| Picture | 引用 OV |
| Sound | 引用 OV |
| Subtitles | 不引用本次新增字幕 |
| Closed captions | 根据项目需求决定 |

### 字幕 MKV

如果字幕封装在 MKV 中：

- 启用对应字幕轨道。
- 选择正确字幕类型。
- 忽略 MKV 的 Video。
- 确认没有意外使用 MKV 的 Audio。
- 确认字幕与 OV 时间轴对齐。

不需要为了添加字幕额外制作全黑视频。

### VF 与 OV 的关系

最终交付需要同时保留：

- OV。
- VF。

不能只交 VF。

## 5. PGS 字幕专用排查

### 问题：MKV 单独预览没有字幕

检查：

- PGS 是否成功封装。
- 是否识别字幕轨道。
- Use as 是否启用。
- 是否选择 Open subtitles。
- Stream 是否选择正确。
- 是否等待解析完成。
- 当前时间点是否存在字幕。

### 问题：MKV 单独预览正常，但 VF 中没有字幕

检查：

- VF 的 Refer to。
- MKV 的 Ignore video。
- Timed text 是否启用。
- 时间轴是否对齐。
- 是否处于字幕出现的时间点。
- 字幕 Position 是否超出画面。

### 问题：字幕位置不合适

不要直接复制其他项目的 Position 数值。

逐步调整并检查：

- 单行字幕。
- 双行字幕。
- 画面上方已有文字。
- 画面下方已有文字。
- 片头、片中、片尾。

本次案例的 DCP-o-matic 2 界面中，Y = 9% 让字幕向上移动，最终视觉效果比 Y = 0% 更合适。

但这只是本次验证结果，不是固定标准。

## 6. 字幕位置修改与重新生成

如果 VF 已经生成，但字幕位置不合适：

1. 打开原 VF 工程。
2. 调整字幕 Position。
3. 重新生成 VF。
4. 再次进行播放验证。

通常不需要重新制作 OV。

因此需要保存：

- OV 工程。
- VF 工程。
- OV 输出。
- VF 输出。
- 使用的字幕源文件。

## 7. 最终验证

使用 DCP-o-matic Player 检查：

- DCP 是否能够读取。
- 字幕是否显示。
- 字幕是否同步。
- 字幕是否被裁切。
- 字幕位置是否正确。
- 画面是否正常。
- 声音是否正常。

然后再使用影院的实际放映服务器进行最终验证。

DCP-o-matic Player 能够播放，不等于影院服务器一定支持所有相同功能。

## 8. 两个 Skill 如何协作

推荐整个项目采用下面的流程：

```text
              项目开始
                 │
                 ▼
       Skill 01：影院条件调查
                 │
                 ▼
       原始素材与硬件检查
                 │
                 ▼
       代表性片段测试编码
                 │
                 ▼
       生成测试 DCP
                 │
                 ▼
       影院实际放映验证
                 │
          ┌──────┴──────┐
          │             │
        不通过         通过
          │             │
          ▼             ▼
       调整参数     Skill 02
          │         正式 DCP 制作
          └──────┐      │
                 │      ▼
                 └──► 正式 OV / VF
                        │
                        ▼
                  DCP-o-matic Player
                        │
                        ▼
                    影院最终验证
                        │
                        ▼
                      交付
```

注意：测试 DCP 的生成也属于 DCP 制作能力，因此两个 Skill 并不是完全独立的先后阶段，而是可以反复调用。

## 10. 经验原则

1. 不要用电脑 HDMI 镜像测试代替 DCP 放映测试。
2. 不要用 DCP-o-matic Player 测试代替影院服务器测试。
3. 不要只看分辨率和码率判断影院画质。
4. 不要忽略制作电脑的编码能力和磁盘空间。
5. 不要认为 DCP 生成成功就意味着交付成功。
6. 不要认为所有字幕格式的制作难度相同。
7. 文本型字幕通常比 PGS 图像型字幕更容易处理。
8. 如果只是修改 VF 字幕位置，通常不需要重新制作 OV。
9. 重要参数必须通过实际预览和放映验证。
10. 影院的实际播放要求优先于软件默认设置和网上经验。

**最终目标不是让电脑能够播放影片，而是让正式 DCP 在目标影院的实际放映系统中，按照预期显示画面、声音和字幕。**
