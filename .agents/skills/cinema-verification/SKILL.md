# 影院适配性与实际放映验证

## 1. Skill 目标

在正式制作和交付 DCP 之前，判断：

1. 原始影片是否适合影院放映。
2. 原始素材的画面、声音、字幕是否存在问题。
3. 电脑是否具备制作 DCP 的硬件条件。
4. DCP 参数是否与影院设备匹配。
5. 通过真正的 DCP 放映验证最终效果。

本 Skill 适用于：

- 使用个人电脑制作 DCP。
- 将网络视频、MKV、MP4 等素材转换为影院 DCP。
- 需要在影院实际放映前进行画质验证。
- 需要确认影院是 2K 还是 4K 放映设备。
- 需要排查电脑播放正常、影院放映效果不佳的问题。

## 2. 必须区分三种验证方式

这是整个 Skill 最重要的原则。

### 方式 A：电脑本地播放

例如使用 VLC 播放原始 MKV。

能够验证：

- 原始视频是否正常。
- 原始音频是否正常。
- 字幕是否正确。
- 暗部、亮部、颜色是否符合预期。
- 原始素材是否存在编码问题。

不能验证：

- DCP 编码后的实际效果。
- DCP 在影院播放服务器上的兼容性。
- 影院放映链路的实际表现。

### 方式 B：电脑通过 HDMI 输出到影院

例如：

```text
Mac
  ↓
播放器（VLC / VTC）
  ↓
macOS 显示合成
  ↓
HDMI
  ↓
影院放映设备
  ↓
银幕
```

这种方式可以验证：

- HDMI 输出是否正常。
- 电脑输出分辨率是否合适。
- 影院投影设备是否能正确接收信号。
- 显示输出的色彩、亮度和黑位表现。
- 电脑镜像或外接显示模式下是否存在画面问题。

但它不是 DCP 放映。

**HDMI 输出的是电脑已经解码、渲染和合成后的显示信号，而不是 MKV 原始 HEVC 数据，也不是最终 DCP 的 JPEG 2000 数据。**

因此：

- 它不能验证 DCP 的 JPEG 2000 编码效果。
- 不能验证 DCP 的 CPL、Reel、字幕资源。
- 不能验证影院播放服务器对 DCP 的解析。
- 不能完整验证 DCP 的音频声道映射。
- 不能代表最终影院播放效果。

本次案例中，使用 Mac 播放 MKV，再通过 HDMI 镜像到影院，属于这种测试。

这种测试有价值，但不能作为最终验收。

### 方式 C：使用真正的 DCP 在影院播放

推荐的最终验证方式：

```text
原始 MKV
   ↓
DCP-o-matic
   ↓
生成 DCP
   ↓
交付影院播放服务器
   ↓
影院放映机
   ↓
银幕
```

只有这种方式才能真正验证 DCP 经过影院播放链路后的效果。

可以验证：

- JPEG 2000 编码后的画面。
- DCP 画幅和缩放。
- DCP 帧率。
- 实际投影分辨率。
- 影院放映服务器兼容性。
- 字幕渲染、位置和同步。
- 音频声道映射和播放效果。

**如果目标是判断影片是否适合影院放映，最终必须使用 DCP 进行实际放映验证。**

## 3. 第一步：确认影院设备条件

在制作 DCP 前，向影院确认以下信息。

| 项目 | 需要确认的内容 |
|---|---|
| 放映机分辨率 | 2K / 4K |
| 放映机型号 | 具体设备型号 |
| 支持的 DCP | SMPTE / Interop |
| 支持的画幅 | Flat / Scope |
| 支持的帧率 | 24 fps 等 |
| 音频 | 支持的声道布局 |
| 放映服务器 | 型号及 DCP 兼容性 |
| VF 支持 | 是否支持 OV + VF 组合 |
| 字幕 | 是否支持目标字幕类型 |
| 加密 | 是否需要 KDM |
| 交付介质 | 影院要求的硬盘及文件系统 |

不要仅仅询问影院有没有 4K 放映机。

还需要确认播放服务器、放映机和交付流程是否共同支持你准备制作的 DCP。

### 2K 放映机与 4K DCP

如果原始视频是 4K，而影院只有 2K 放映机：

- DCP 可以制作成 4K。
- 但最终投影的实际分辨率受到 2K 放映设备限制。
- 播放链路可能需要进行缩放。
- 不能期待 4K DCP 在 2K 放映机上显示出完整的 4K 细节。

是否应该制作 2K DCP，需要结合影院要求、素材质量和制作时间决定。

不要把 DCP 的分辨率和投影机的物理分辨率混为一谈。

## 4. 第二步：确认制作电脑是否具备条件

制作 DCP 与普通播放视频不同。

DCP-o-matic 需要解码原始素材，并将视频重新编码为 JPEG 2000。

尤其是 4K、10-bit、长时间影片，可能需要较多的计算资源和存储空间。

### 4.1 CPU

重点关注：

- CPU 型号。
- 核心数。
- 多核持续负载能力。
- 长时间编码时的散热和降频情况。

JPEG 2000 编码可能需要较长时间。

不能仅仅根据电脑能够流畅播放 4K 视频，就判断它能够快速制作 4K DCP。

### 4.2 GPU

需要区分：

- GPU 是否支持原始 HEVC 硬件解码。
- DCP-o-matic 实际使用什么解码方式。
- JPEG 2000 编码是否依赖 CPU 或其他加速方式。

不要默认 GPU 能够加速所有 DCP 编码过程。

### 4.3 内存

重点关注：

- 原始视频分辨率。
- 视频编码复杂度。
- DCP-o-matic 同时处理的任务。
- 长时间编码时的内存使用情况。

不要仅根据系统最低配置判断能否顺利处理长片。

### 4.4 硬盘空间

这是个人电脑制作 DCP 时非常容易忽略的问题。

以本次影片为例：

- 时长：约 9562 秒。
- 视频目标码率：150 Mbps。
- 视频估算体积：约 179.3 GB。
- 5.1 PCM 音频估算体积：约 8.27 GB。
- OV 总体积：约 188 GB。

还需要额外空间存放：

- 原始 MKV。
- 封装字幕后的 MKV。
- DCP-o-matic 临时文件。
- OV。
- VF。
- 重新生成的版本。
- 其他验证文件。

建议不要只按照最终 DCP 大小准备磁盘空间。

应该为整个工作流程预留充足空间，并优先使用可靠、写入性能稳定的存储设备。

### 4.5 实际硬件验证

不要只凭硬件参数判断。

建议：

1. 创建一个短片测试工程。
2. 使用与正式项目相同的分辨率、帧率和编码参数。
3. 实际执行 JPEG 2000 编码。
4. 观察 CPU、GPU、内存、温度和磁盘使用情况。
5. 测量实际编码速度。
6. 根据结果估算整部影片的处理时间。

例如：

```text
测试片段：10 分钟
实际编码耗时：20 分钟

编码速度：0.5 倍实时速度

影片时长：159 分钟

预计编码时间：约 318 分钟
```

这是一个估算示例，不代表实际设备一定达到这个速度。

## 5. 第三步：检查原始视频是否适合影院

在制作 DCP 前，先检查原始素材。

### 画面检查

重点关注：

- 分辨率。
- 画面比例。
- 帧率。
- 码率。
- 色彩空间。
- SDR / HDR。
- 暗部细节。
- 高光细节。
- 噪点。
- 压缩伪影。
- 画面是否存在黑边。
- 是否存在意外裁切。

### 暗部画面特别检查

本次案例曾经遇到：

- 电脑播放时暗部清楚。
- 影院播放时暗部模糊。
- 原本纯黑的地方出现不均匀灰色区域。

排查时要区分：

1. 原始视频本身的问题。
2. 播放器解码和渲染问题。
3. HDMI 输出和色彩格式问题。
4. DCP 编码问题。
5. 影院放映设备和播放链路问题。

不能把所有问题都归因于码率。

建议准备：

- 纯黑测试画面。
- 深灰测试画面。
- 暗部细节丰富的影片片段。
- 高亮画面。
- 运动画面。

先通过电脑和 HDMI 测试排除明显的显示链路问题，再使用 DCP 验证最终结果。

## 6. 第四步：通过 DCP 进行影院验证

这是本 Skill 的最终阶段。

### 测试 DCP 的制作原则

测试 DCP 应尽量接近正式交付版本：

- 使用相同的画幅。
- 使用相同的分辨率。
- 使用相同的帧率。
- 使用相同的视频码率策略。
- 使用相同的音频声道布局。
- 使用正式字幕资源。
- 使用正式 OV / VF 结构（如果最终交付采用 OV/VF）。

如果正式项目是 4K Flat 24 fps，那么测试 DCP 最好也采用这些参数。

否则测试结果不能充分代表正式交付效果。

### 测试内容选择

不一定每次都要把整部影片制作成 DCP 才能初步判断。

可以先制作一段具有代表性的测试片段，但必须注意：

- 测试片段应保留正式制作的参数。
- 应包含暗部、亮部、快速运动、字幕等关键场景。
- 测试片段 DCP 只能作为预检。
- 最终完整影片仍然需要进行完整性和播放验证。

### 影院实际验证清单

| 验证项目 | 检查内容 |
|---|---|
| 画面比例 | 是否被裁切或拉伸 |
| 分辨率 | 是否符合预期 |
| 清晰度 | 细节是否正常 |
| 暗部 | 是否有明显丢失或模糊 |
| 高光 | 是否过曝 |
| 色彩 | 是否异常偏色 |
| 黑位 | 是否出现不均匀灰色 |
| 帧率 | 是否有卡顿 |
| 音频 | 是否正常播放 |
| 声道 | 是否正确映射 |
| 字幕 | 是否正常显示 |
| 字幕位置 | 是否被裁切或遮挡 |
| 同步 | 字幕与对白是否同步 |
| 播放服务器 | 是否能够正常播放 |

### 最终结论

影院验证应形成明确结论：

- 通过：可以按当前参数制作正式 DCP。
- 有条件通过：存在可以接受或需要调整的问题。
- 不通过：必须调整素材、参数或制作方案后重新测试。
